# 計画01：Windows 音声入力

更新日：2026-11-26。開発中ソースは公開済み、Windows アプリの正式配布前。

## 今回の範囲と成功条件

既存の合成音声、取得済みモデル、配布候補の実行部だけを使い、追加取得や録音を伴わない比較を進める。成功条件は、既存記録と今回の実測を区別し、`large-v3-turbo` の比較結果、採否に足りない条件、実マイクでの次の操作を残すこと。製品コード、モデルの既定値、共有設定、Pi 本体・版は変更しない。

**計画01全体は未完了。** 実マイクの待ち時間と最低動作スペックは未確定。今回の合成音声の比較を、その完了扱いや正式配布の合格扱いにしない。

## 既存結果として確認したこと

[開発進捗](../progress.md#音声入力の高速化計画01) と公開対象外の既存試験結果を照合した。

- `large-v3`、日本語指定、Vulkan 同梱の Windows x64 展開候補で、6.945秒の合成音声を停止してから編集済み下書きへの追記まで5.40秒、5.27秒。オフライン、取消、録音中の下書き編集、許可拒否の確認を含む。今回の再実行ではない。
- 同じ既存候補では、GPU を使えなくした条件で CPU に復帰し、下書きへの追記まで29.25秒。新規・既存チャットで Enter による送信はローカルの模擬モデルへ各1件。今回の再実行ではない。
- 実マイクでの聞き取りと会話への追加は既存記録にある。実マイクの停止から追記・送信までの時間は、既存試験が待機終了や接続エラーを含むため確定していない。実ユーザーの音声・認識本文は今回読み出していない。
- 既存の CPU 比較は合成4本を各1回。日本語指定の `large-v3` は18.9〜24.3秒、ピーク約3,930 MiB。`large-v3-turbo` は14.2〜16.0秒、ピーク約1,827 MiB。プロセス開始から終了までで、録音停止から下書き反映までの時間とは区別する。

実装では GPU 側の上限が60秒、CPU 側が120秒。GPU の失敗時は同じ音声・モデル・言語で CPU を一度試す。したがって、復帰時の利用者の待ち時間には GPU の待ち時間も加わり得る。[実行処理](../../../apps/desktop/electron/platform/voice-input.ts)

## 今回実行した比較

既存の配布候補に同梱された `whisper.cpp` v1.9.5 の Vulkan 実行部を直接実行した。アプリのモデル選択や保存済み設定は変更していない。

| 条件       | 内容                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 実機       | Windows x64、RTX 4060、GPU メモリ表示8,188 MiB                                            |
| ドライバー | 621.40。既存記録の621.24と異なるため、過去の速度と同一条件とは扱わない                    |
| 入力       | 取得済み合成4本：日常会話、Python/API、Electron/ポート番号、HTTP障害対応                  |
| 音声の長さ | 6.945秒、7.100秒、8.410秒、14.210秒                                                       |
| モデル     | 取得済み `large-v3` と `large-v3-turbo`                                                   |
| 実行条件   | 日本語固定、6スレッド、標準入力から WAV、タイムスタンプなし、各試行でモデルを読み込み     |
| 回数       | 各モデル・各音声2回。2周目はモデルの実行順を逆にする                                      |
| 時間       | プロセス開始から終了まで。モデル読み込み、観測処理の待ち時間を含む                        |
| キャッシュ | OS・ドライバーのキャッシュを消していない。今回最初の試行と後続試行を区別する              |
| 終了制限   | CLI 比較は90秒。製品の GPU 制限60秒とは異なる                                             |
| メモリ     | 実行プロセスのピーク使用量。GPU はデバイス全体から試行直前の使用量を引いた概算            |
| 文字比較   | NFKC、大文字小文字・空白・句読点を除去。各周回195文字。数字の漢字・算用数字は同一化しない |

比較スクリプトは終了コード0。16試行すべて終了コード0で、各ログの実行先が `Vulkan0` であることを確認した。各モデルの今回最初の試行と、それ以降の7試行を分ける。

| モデル           | 今回最初の試行 |    後続7試行 | ピーク RAM | GPU 使用量の増加 | 文字誤り（各周回） |
| ---------------- | -------------: | -----------: | ---------: | ---------------: | -----------------: |
| `large-v3`       |        45.30秒 | 4.71〜7.05秒 |  435.2 MiB | 4,004〜4,023 MiB | 14 / 195、14 / 195 |
| `large-v3-turbo` |         5.88秒 | 2.67〜3.46秒 |  334.3 MiB | 1,895〜1,905 MiB | 15 / 195、15 / 195 |

今回の条件では `turbo` の後続処理が短く、GPU 使用量の増加も小さかった。`large-v3` の今回最初の試行は45.30秒で、読み込み時間だけでも14.54秒だった。キャッシュを消した試験ではないため、これを未使用環境の初回時間の保証にはしない。今回すべて60秒以内だったことも、製品経路の待ち時間や他の GPU での保証にはならない。

両周回の出力はモデルごとに同じだった。`turbo` は「バージョン」を参照どおりに認識した一方、`README` がカタカナとなり、`Electron` も両モデルでカタカナになった。両モデルとも `3.12`、`8080`、`14時35分`、`503`、`25秒`、`40秒` を維持した。`turbo` の製品採用は保留する。

合成4本は速度と限られた語句の比較用である。数字の表記差も誤りに数えるため、文字誤りの総数だけで聞き取り品質やモデルの優劣を決めない。各試行の終了結果と Vulkan 使用を実行ログで確認する。GPU 使用量の差分は他プロセスの影響を受け、最低 VRAM 要件を意味しない。

## 未確定条件と次の最小手順

1. **実マイクの待ち時間を確定する。** 利用者が録音を行えるタイミングで、既存 `large-v3`・日本語指定の配布候補を使う。個人情報のない決めた短文を読み、音声の長さ、停止から編集可能な下書きへの追記まで、Enter 停止から送信までを分けて測る。初回と2回目以降を区別し、各経路を最低2回記録する。GPU を使ったか、CPU へ復帰したかも記録する。認識本文や録音を公開資料へ保存する必要はない。
2. **30秒上限の条件を確認する。** 現在の比較の最長は14.210秒。上限までの音声で処理時間と取消を確認し、CPU 復帰時も含めて下書きの保持を確かめる。今回勝手に長い録音を作らない。
3. **最低動作スペックを実機で決める。** 同梱 CPU 実行部の AVX2 前提と、既存計測で約3,930 MiB の実行プロセス使用量がある。OS や Electron の使用量を含まないため「RAM 4 GBで動く」とは案内できない。GPU がない対象機、少ない RAM の対象機など、実際に案内したい構成で同じ配布物を確認する。メモリ制限や GPU 非表示だけの試験を低性能機の合格に置き換えない。
4. **モデル採否を決める。** 現行は `large-v3` を維持する。`turbo` の製品採用を検討する場合は、今回の CLI 比較に加え、採用予定の配布候補・実マイク・数字や技術用語で品質と待ち時間を確認する。取得時の検証とモデル保存の互換性も対象とし、比較だけを理由に製品のモデルを差し替えない。
5. **最終配布候補で再確認する。** 計画04・05が確定した同じ配布物で、オフライン、初回と後続起動、取消、下書き保持、GPU 不可時の CPU 復帰を確認する。今回の CLI 成功はアプリ全体や最終配布物の合格を兼ねない。

今回、新規モデル取得、マイク録音、実ユーザーデータ・認証・共有設定の読み出しは行っていない。CPU・搭載 RAM の CIM 照会は環境の制限で取得できず、最低スペックの新たな根拠にはしていない。

## 計画01の完了条件

- 同じ素材・同じ対象配布物で待ち時間、認識の違い、必要メモリを記録した。
- オフライン、取消、下書き保持、CPU 復帰を対象配布物で確認した。
- 実マイクの聞き取りと、停止から下書き・Enter 送信までの待ち時間を確認した。
- 最低動作スペックとモデル採否を、対象実機の結果と利用者の判断で確定した。
- 未確認や失敗の条件を含めて共有の進捗へ反映した後、担当チャットのアーカイブ可否を案内する。
