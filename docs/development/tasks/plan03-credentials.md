## 今回進めた独立作業

専用 Windows 試作の保管処理、独立設定画面、合成試験と、共有ソースのカスタム接続先取得・保存・IPC を照合した。共有ソースでは `CustomProviderEntry.apiKey` が `AppStore.listCustomProviders()`、`CustomProviderConfig` を通り、設定画面の初期入力値へ渡る。取得契約と入力契約を同じ型で表しているため、単にパスワード欄を空にする変更だけではキー返却を廃止できない。

- 調査対象：[共有ストア](../../../packages/pi-sdk-driver/src/custom-provider-store.ts)、[共有の型](../../../packages/pi-sdk-driver/src/custom-provider-types.ts)、[IPC 契約](../../../apps/desktop/contracts/ipc.ts)、[設定取得](../../../apps/desktop/electron/application/app-store.ts)、[設定画面](../../../apps/desktop/src/features/settings/settings-custom-endpoints-section.tsx)。
- 今回の合成試験は、毎回新規の一時プロファイルを作り、認証に関係する周辺の環境変数を引き継がず、外部 `fetch` を禁止して実行した。実ユーザーの認証・会話・セッションは使っていない。
- Pi の公開 `ModelRuntime.create`、`listCredentials`、`getProviderAuthStatus`、`getAuth`、`registerProvider` のみで確認した。Pi の内部実装に変更を加えていない。
- コマンド参照の一覧取得と状態表示では、実行を数えるための合成ファイルは作られなかった。試験前後の一時 `auth.json` と `models.json` は一致した。
- コマンド解決では Git Bash の起動が終了値 `3221225794`（`0xC0000142`）で失敗した。Pi は起動できたシェルの非正常終了から既定シェルへ再試行しない。この環境では `auth.json` のコマンド参照はキー未解決、`models.json` のコマンド参照は `auth` エラーになった。Pi 本体や OS を変更せず、環境上の障害として残した。
- 合成 OAuth は、ログインを禁止するコールバックと合成の更新関数を登録し、期限切れトークン4件の同時解決で更新が1回だけ実行されること、新しい合成トークンが一時ファイルに保持されること、モデル設定が変わらないことを確認した。

合成試験は3件成功。ただし、うち2件はシェル利用不可時の拒否と一覧取得の確認であり、コマンド解決成功を示すものではない。実行用コードと再現方法は公開対象外の担当検証資料へ保存した。製品実装を変更していないため、既存 Windows 画面試験や共有ソース全体の検査の合格を今回新たに主張しない。

今回の担当文書と合成試験の整形・JavaScript 構文検査は成功。共有作業ツリーの `pnpm check:identity` は終了コード0、857ファイルを走査して clean だった。これは実キーや個人情報が存在しないことの完全な証明ではないため、担当差分を目視でも確認した。

## 製品へ移す契約

### 取得と入力を分ける

| 操作                     | renderer から送る値                       | renderer へ返す値・拒否条件                                                                  |
| ------------------------ | ----------------------------------------- | -------------------------------------------------------------------------------------------- |
| 一覧・編集開始           | 登録 ID                                   | ID、URL、モデル、保護状態、キーの有無、版番号。キーと認証参照の内容は返さない                |
| 保持                     | ID、版番号、設定、`keep`                  | キーを読み返さない。キーがある接続先の URL 変更を拒否                                        |
| 交換                     | ID、版番号、設定、`replace`、新しい入力値 | 新しい値を暗号化して保存。成功・失敗応答に入力値を含めない                                   |
| キー削除                 | ID、版番号、`delete`                      | キーなしの状態を返す。保護対象では Pi 認証・環境変数・プレースホルダーへフォールバックしない |
| 登録削除                 | ID、版番号、明示した削除操作              | 保護情報とキー参照を無効化し、対象ランタイムを更新する                                       |
| 保存済みキーでモデル取得 | 登録 ID と版番号                          | main が保存済み登録から URL を決め、所定の `/models` だけを照合して送信する                  |
| 新規入力を試す           | 未保存の URL と入力した新しい値           | 保存済みキーを ID から自動補充しない。登録済みキーの取得契約とは分ける                       |

空欄は既存キーの保持を表す表示にし、削除は明示操作にする。新しいキー入力は成功時と編集取消時に破棄する。入力・取得・エラー・状態配信・デバッグ情報のすべてで、キーを文字列展開しない。Pi のエラーにはコマンド文字列やファイル情報が含まれる場合があるため、製品 IPC は定型コードへ変換し、日本語の確認案内だけを表示する。

登録 ID は不変とし、保管内容を ID・正規化 URL・許可する API・保護方式・版番号へ結び付ける。複数画面や複数プロセスの保存競合は、版番号の不一致で再読込を求める。独立試作の Promise キューは単一インスタンスの直列化だけを担うため、製品の複数プロセスでの更新を保証する仕組みとして流用しない。

### 保管と送信

Pi-GUI 専用領域に、非秘密メタデータと暗号文を保存する。暗号化した内容にも登録 ID と宛先を含め、復号時に対応を照合する。暗号化が利用できない、保管内容が壊れている、登録と一致しない場合は送信を拒否し、平文保存へ切り替えない。

復号したキーを Pi の `CredentialStore`、`getAuth` の結果、拡張へのコールバック、会話イベントへ渡さない。最終 URL と方式・許可 API の完全一致を確認した送信側だけが認証を付ける。会話・タイトル・引き継ぎ下書き、再送・要約・キャッシュ事前更新・仮想モデルの物理モデル解決に同じ登録を適用する。モデル一覧取得は `/models`、モデル送信は `/chat/completions` を別の許可操作として定義する。

送信開始時に登録の版を固定する。交換・削除は以後の送信へ適用し、既に開始した通信の取消・完了の扱いを明示する。設定変更後に古いキーをキャッシュした別ランタイムが新規送信しないことを試験する。

この構成で保存時の暗号化と送信先制限を製品へ移せても、同じプロセスの拡張からキーを守る証明にはならない。隔離を掲げるには、キーを扱う送信側をエージェント・拡張と分離し、Windows の制約を実測する必要がある。

## 既存設定と移行

既存ファイルの自動移行は行わない。CLI と GUI が現在使う Pi の `auth.json`、`models.json` は維持する。キーの代わりに `unused` を既存ファイルへ書き戻す方法は採用しない。Pi 側ではその文字列自体がキーとして解決され、CLI の互換性を壊すためである。

| 既存の形                           | 製品移行時の扱い                                                             | 検証条件                                                                            |
| ---------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 平文の GUI カスタム接続先          | 一覧へキーを返さず、既存経路として表示。保護対象へは利用者が新規に再登録     | 元ファイル不変、旧経路と保護経路で別々のダミーキーだけが届く                        |
| 環境変数参照                       | 参照を維持し、一覧表示で解決しない                                           | 環境変数あり・なし、CLI/GUI 併用、保護キー削除後に流用されない                      |
| コマンド参照                       | 元の Pi 解決に委ね、一覧・編集開始で実行しない                               | 正常な Windows シェルで成功・失敗・空出力・再実行条件を確認。現在はシェル障害が残る |
| OAuth                              | Pi の認証・更新を維持し、保護対象の API キーへ変換しない                     | 今回の合成更新に加え、UI 併用・取消・失敗表示を検証。実ログインは別途扱う           |
| 同じプロバイダー ID に別の既存認証 | 自動採用・優先順位の暗黙変更をしない。保護登録は一意な ID を使い、衝突を拒否 | API キー、OAuth、環境参照、拡張による再登録との衝突で未登録先0件                    |

移行後も旧ファイルに元のキーが残る場合、旧経路への保存時保護や送信先保護が追加されたとは表示しない。旧キーの削除や実キーの移動は、この作業では実施しない。既存 GUI 登録の判定にはマーカーのない互換エントリーも含まれるため、現行ストアの認識を所有権や自動移行の許可と同一視しない。
