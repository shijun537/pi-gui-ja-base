## 今回の実行方法

既存の担当チャットの読み取りと、担当06への再開指示の送信を試したが、調整用アプリへの接続エラーで到達・再開を確認できなかった。既存チャットが再開したとは扱わない。今回の調整作業内で01〜06を並列担当へ分担し、各担当は上の専用文書と自分の検証領域だけを編集する。共有の README・進捗・引き継ぎ・公開 main は調整担当が統合する。

既存の担当チャットは保持する。各担当文書の末尾に、そのチャットへ渡せる再開プロンプトを置く。直接の送信が使える状態へ戻ったら、実行中かと最新結果を確認してから送る。同じ作業を重複して実行しない。03〜06は完了記録後に利用者へアーカイブを案内し、先に閉じない。

## 実行順と完了条件

1. 01〜06の独立した調査・合成試験・修正候補作成を並行して進める。できたことと、追加の環境・判断が必要なことを各担当へ記録する。
2. 02・03・04・06から、採用範囲、認証互換、ランタイム、識別子、保存先、更新・署名の構成をそろえる。未検証の試作を共有ソースへ自動的に採用しない。
3. 05が同じ構成の配布候補を作り、ショートカット選択あり・なし・無人、上流版との同居、完全なアンインストール、保存先を検証する。更新を採用する場合は02の復旧・署名検証も同じ候補で確認する。
4. 紹介サイトはビルド成功と配信成功を分ける。Pages の設定、deploy 成功、公開 URL の表示と主要リンクを確認する。配布物の公開は、候補の検証と案内がそろってから扱う。
5. 公開する差分の混入・リンク・対象検査を実行し、親の作業ツリーと上流履歴を保持して指定リポジトリへ反映する。リモートと候補を照合する。

## 守る条件

- Pi 本体と共有設定は変更しない。Pi の版変更は利用者への事前確認が必要。
- ダミーキー・合成データ・一時プロファイルを使う。実ユーザーの会話、認証、保護ソフトの未加工の画面や私有ログを公開しない。
- OS の保護設定や検査を無効化して成功扱いにしない。実際のマイク・クリップボード・セットアップが確認できない場合は、別の種類の試験で置き換えない。
- 証明書の発行者や最低スペックを創作しない。有料契約、新しい資格情報、未検証のバイナリ公開を追加しない。
- 今回は使用量取得も接続エラーで、5時間枠の残量は不明。以前の使用量・リセット時刻を使わない。取得できる場合はその時点を基準にし、残り2%で停止する。
